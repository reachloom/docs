An API key is a long secret that lets a client use one Reachloom workspace without signing in. You create it once, paste it into your client, and it works until you revoke it.

Use a key for scripts, CI jobs, servers, and any client that cannot open a browser. For everyday use on your own computer, [OAuth](/ai/mcp-oauth) is easier.

## Create a key

<Steps>

1. Open **Settings → Developer API** in the workspace you want the agent to use.

2. Under **API keys**, type a name. Use the name of the tool that will use the key, like “Claude Code” or “Nightly script”.

3. Click **Create key**.

4. Copy the key right away. Reachloom shows it only once.

</Steps>

A key looks like this:

```txt
rl_live_k3Jx...
```

It always starts with `rl_live_`. Reachloom keeps only a hashed copy, so it cannot show you the key again. If you lose it, revoke it and make a new one.

A workspace can have up to 20 active keys. Give each tool its own key, so you can revoke one without breaking the others.

## Use the key

Send the key in the `Authorization` header on every request to the MCP server:

```http
Authorization: Bearer YOUR_API_KEY
```

<Tabs syncKey="client">
<TabItem label="Claude Code">

```sh
claude mcp add --transport http reachloom https://my.reachloom.app/mcp \
  --header "Authorization: Bearer YOUR_API_KEY"
```

</TabItem>
<TabItem label="Cursor">

Add this to `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "reachloom": {
      "url": "https://my.reachloom.app/mcp",
      "headers": { "Authorization": "Bearer YOUR_API_KEY" }
    }
  }
}
```

</TabItem>
<TabItem label="curl">

A quick test of the key. This asks the server which tools it has:

```sh
curl -i https://my.reachloom.app/mcp \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

A `401` answer means the key is missing, wrong, revoked, or its creator no longer has workspace access. A successful response lists the tools. Other errors can indicate a request or server problem.

</TabItem>
</Tabs>

Replace `YOUR_API_KEY` with your key. For another Reachloom address, use the address shown in your MCP setup page.

## What a key can do

A key belongs to one workspace and the person who made it. It can read workspace data, prepare campaigns and pages, and write drafts. It cannot send, approve, switch campaigns on, delete data, or change settings. Workspace usage limits still apply.

<Aside type="danger" title="Keep keys secret">
Do not put a key in Git, in a public prompt, in a screenshot, or in a shared chat. Use an environment variable or your client's secret store. Anyone with the key can read that workspace and prepare work in it.
</Aside>

## See, check, and revoke keys

The **API keys** list in the workspace's **Settings → Developer API** shows each key's name, the first characters of the key, when you made it, and when it was last used. “Never used” means no client has called the server with that key.

Click **Revoke** to turn a key off. It stops working at once, and you cannot undo it. Make a new key if you still need access.

If you think a key leaked, revoke it first. Then create a new one and update your clients.

## Limits

Reachloom allows up to 120 MCP requests per minute for each person and workspace. When you go over, the server answers `429` with a `retry-after` header. Wait and try again.

For all the technical details, see [Authentication](/api/authentication#api-keys).
