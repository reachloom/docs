Connect your agent through [MCP](/ai/mcp) first. These workflows prepare work for you to review in the dashboard.

## Prepare a campaign

> Create a paused campaign called Resource lists. Ask maintained lists of monitoring tools to add our product. Find 20 pages and prepare five emails. Leave everything as drafts.

The agent can:

1. Read `get_status`.
2. Call `create_campaign` with `kind: "list"`.
3. Follow the returned `searchTaskId` with `get_task`, if present.
4. Use `update_brief` to refine the target, angle, and exclusions.
5. Read `list_pages`, then call `write_emails`.
6. Show the drafts from `list_emails`.

The first search starts when the campaign is created, so wait for it before starting another search. Open **Inbox → Drafts** to review the emails. The agent cannot approve them or switch the campaign on.

## Add pages you found

> Add these three page addresses to the paused campaign, then show me its pages. Do not invent contact details.

Use `add_pages` with `campaignId` and `urls`, then `list_pages`. The tool accepts page addresses only. Add contact emails in the dashboard or use `find_leads` to discover verified public addresses.

## Catch up on replies

> Check the Inbox, list conversations waiting for us, and draft an answer to this question. Leave it for me to send.

Use `check_inbox`, `list_conversations`, `read_conversation`, then `draft_reply`. The saved answer stays a draft. If your own answer is already waiting, the tool leaves it alone.

## If a tool refuses a change

An active campaign that sends without review cannot be changed through MCP. Pause it or enable **Review before sending** in the dashboard, then retry.

A usage-limit error applies to all ways of working in the workspace. Check [billing and usage](/account/plans) rather than starting the same job through another client.
